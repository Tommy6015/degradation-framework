# Requirements

**Source**: the master thesis task sheet (issued 2026-09-02, submission 2027-03-02), title
*Development and Evaluation of a Modular Framework for Generating Degraded Camera Data for Stationary Infrastructure Cameras*.

**Purpose**: to provide camera data with degradations of known type and intensity, reproducibly, for developing and evaluating **camera self-monitoring** methods.
Real recordings do not cover all relevant states and do not allow varying a single factor on its own; synthetic data does, provided that the models used are selected, parameterised and evaluated traceably.

**Scope**: the five subtasks of the task sheet. This repository covers the implementation of the framework (subtask 3) and the tools that support the evaluation (subtasks 4 and 5);
the research and justification (subtasks 1 and 2) go into the thesis, and key conclusions are kept as [decision records](decisions/README.md).

Before a feature is developed, the corresponding requirements are taken from here as its acceptance criteria (see the conventions in [README.md](README.md)).

## Terms

- **Local degradation**: affects only part of the image, e.g. lens soiling, raindrops (water drops on the lens), occlusion.
- **Global degradation**: affects the whole image, e.g. fog, snow (falling snow), poor exposure, blur, noise.
- **Intensity level**: a common set of levels for each degradation (e.g. levels 1–5); each level maps to a concrete set of parameters (e.g. the visibility of fog in metres).
- **Dataset adapter**: connects a dataset's organisation (images, sequences) and annotation format to the framework's common representation, and writes them back in the original format on export.
  The framework is not tied to any one dataset; adding a dataset means adding one adapter. TUMTraf (A9) is the first example.

| ID | Requirement | Subtask | Acceptance | Status |

| F1 | Read image datasets and **camera sequences** from **different sources** through **dataset adapters**; the framework is not tied to one dataset; the first example is TUMTraf (A9) | 3 | At least two sources (a plain image folder, the TUMTraf adapter) go through the same pipeline; covered by tests | 🟡 Plain image folder ✅; TUMTraf point clouds and calibration ✅ (used by the fog, [decision 0008](decisions/0008-fog-lidar-depth-scale.md)); adapter interface, TUMTraf images and annotations, sequences ❌ |

| F3 | Provide representative **local and global degradations**: soiling, raindrops, occlusion, fog, snow, poor exposure, blur; at least one method each, with a justified selection (see D2) | 2, 3 | Each degradation integrated into the framework and tested; the selection written as a decision record | 🟡 Fog ✅; soiling / water drops vendored, not integrated; the rest ❌ |
| F4 | Each degradation has **intensity levels**; the mapping from level to parameters is justified and documented; parameters can also be given directly | 3 | A level table for each degradation; results generated by level get monotonically stronger | ❌ |

| F7 | **Preview** before generating a whole dataset: see the effect of different degradations and intensities on selected images | 3 | A working preview UI or command, covering all integrated degradations | 🟡 Initial Gradio version, not up to date with new features |
| F8 | **Export**: degraded images / sequences, the **existing annotations** (in the dataset's original format, one-to-one), degradation metadata (type, intensity, parameters, seed), and **masks** of local degradations | 3 | The exported dataset can be read directly by the original dataset's tools / detection code; metadata and masks complete | 🟡 Images and parameters ✅; annotations, masks ❌ |

| F10 | All choices (dataset / subset, degradations, intensities, seed) are written in a **configuration file** that can be saved and reused | 3 | One configuration file fully describes a generation run | 🟡 Degradations, parameters, seed ✅; dataset, subset, intensity ❌ |
