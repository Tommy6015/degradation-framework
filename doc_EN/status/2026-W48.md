- **Water drop size measured and the cause analysed** (no code changed):
  - Measured with 10 seeds per SIZE, on 960×960 and 1920×1200 images:
    - for SIZE between 0.1 and 0.3, the actual size is about 0.8 times the nominal size, but it varies by a factor of 2 to 3 between seeds;
    - at SIZE ≤ 0.1, sometimes no drop is generated at all;
    - at SIZE ≥ 0.4 drops split into several; at 0.6 the whole image is covered.
  - Cause: the generator network only takes SIZE as a hint, and nothing constrains the size of its output; the blur, the 0.5 threshold and the splitting afterwards add to the deviation.
  - Plan for M4: the network only gives the shape, and position and size are set exactly by us; in pixels first, later convertible to millimetres.
  - The findings are in section 5.1 of [commands.md](../commands.md).
- **Command line usage written up** (`a5fc2b3`):
  - [commands.md](../commands.md) collects the PowerShell commands for each feature, each with fixed values and with input at run time, plus caveats and common errors;
  - it is linked from `doc/README.md` and the root `README.md`.
- **Fog: depth corrected with LiDAR** (11-24, [decision 0008](../decisions/0008-fog-lidar-depth-scale.md)):
  - Measured: with Depth Pro alone, the depth on the TUMTraf A9 roadside camera is only about 1/8 of the LiDAR measurement, so fog at a visibility of 100 m looks like about 800 m;
    but the ratio is very stable, so the relative structure is right and the overall scale is wrong.
  - `degfw fog --lidar FOLDER`: finds each image's point clouds and calibration in the TUMTraf labels, projects the points into the image,
    and corrects Depth Pro's scale by the median ratio; without a point cloud the image falls back to Depth Pro only.
  - New modules: `core/lidar.py` (read PCD, project, fit the scale; dataset independent), `datasets/tumtraf.py` (read the TUMTraf labels).

## Problems and risks

- **With Depth Pro alone, the fog intensity cannot be trusted**: on roadside cameras the depth is about 8 times too small, so fog at a nominal visibility of 100 m looks like about 800 m.
  Data with LiDAR is fixed by `--lidar`; for datasets without LiDAR there is no solution yet, to be decided with the intensity levels (F4) (open decision 5 in the roadmap).
- **The size of water drops (and of the other two contamination types) cannot be controlled**: the actual size for the same SIZE varies by a factor of 2 to 3.
  The task sheet asks for degradations of known type and intensity, so this must be solved before the integration into the framework (M4); the intensity levels (F4) depend on it too.
- **For images without sky, the fog depends on the batch**: the same image can get a different fog colour in different batches, and the fog may jump from frame to frame in a sequence.
  To be solved before datasets are generated (open decision 3 in the roadmap).
- **Semi-transparent soiling is very slow**: the noise is computed pixel by pixel in pure Python, for the whole image again for every spot and every scale; large images take a long time.
  Needs to be sped up before datasets are generated in bulk.
- **The contamination models' weights can only be loaded on CUDA** (noted last week).
