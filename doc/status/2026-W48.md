  - 实测：每个 SIZE 用 10 个种子，960×960 和 1920×1200 两种图。
    - SIZE 在 0.1 到 0.3 之间时，实际大小约为名义大小的 0.8 倍，但不同种子之间能差 2 到 3 倍；
    - SIZE ≤ 0.1 时，有时一个水滴都不生成；
    - SIZE ≥ 0.4 时会裂成好几块，到 0.6 盖满全图。
  - 原因：生成网络只把 SIZE 当作参考，并没有约束输出的大小；后面的模糊、0.5 阈值和拆分又放大了偏差。

## 问题与风险

- **只用 Depth Pro 时，雾的强度不可信**：路侧相机上景深约小 8 倍，标称能见度 100 m 的雾看起来约 800 m。
  有 LiDAR 的数据用 `--lidar` 解决；没有 LiDAR 的数据集还没有办法，和强度等级（F4）一起定（roadmap"要决定的事"第 5 条）。
- **水滴（以及另外两种污染）的大小不可控**：同一个 SIZE 的实际大小能差 2 到 3 倍。
  任务书要求退化的性质和强度已知，所以接入框架（M4）前必须解决，强度等级（F4）也要用到。
  水滴的位置已经精确（决策 0009），大小下一步按同样的思路做；不透明和半透明污渍的位置仍只是参考。
- **水滴的默认结果变了**：同样的参数和种子，水滴的位置和形状都和以前不同。以前生成的水滴图要复现，加 `--droplet-placement network`。
- **没有天空的图，雾的结果取决于批次**：同一张图放进不同的批次，雾的颜色可能不同，序列里可能逐帧跳变。
  正式生成数据集前要解决（roadmap"要决定的事"第 3 条）。
- **半透明污渍很慢**：噪声是逐个像素用纯 Python 算的，每块污渍、每个尺度都要把整张图算一遍，大图要等很久。
  批量生成数据集前要加速。
- **污染模型的权重只能在 CUDA 上加载**（上周已记）。
