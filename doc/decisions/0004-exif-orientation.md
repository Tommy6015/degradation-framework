# 0004：读图时按 EXIF 方向转正；雾的 RGB 和景深来自同一份像素

- 状态：已采纳
- 日期：2026-11-19
- 相关：`core/io.py`（`load_rgb_u8`、`load_image`）、`degradations/weather/fog.py`（`Clear2Fog.load`）；提交 `7a2e74d`

## 背景

手机竖拍的照片在文件里是横着存的，另外带一个 EXIF 方向标记。

- Clear2Fog 的 `c2f.py` 读 RGB 时不按标记旋转，Depth Pro 读同一个文件算景深时却会旋转。
  旋转 90° 的照片两者尺寸对不上，处理失败；旋转 180° 的照片不报错，但景深是倒的，雾悄悄加错。
- 框架自己的 `load_image` 也不按标记旋转：竖拍照片按横着的样子处理和保存。

## 决定

- `core/io.py`：读图时用 `ImageOps.exif_transpose` 按标记转正（8 种方向都处理），再统一转成 RGB。
  所有入口（`degfw run`、`apply`、GUI、脚本）读到的都是转正后的图；输出文件不带方向标记。
- 雾：`Clear2Fog.load` 用同一份转正后的像素算 RGB 和景深；EXIF 里的焦距照样用。

## 考虑过的方案

- **保持 `c2f.py` 的行为**：带标记的照片会失败或出错。
- **只按 Depth Pro 的方式处理 3/6/8 三种方向**：镜像的方向（2/4/5/7）就处理不了。
- **只在雾的适配器里处理**：其他退化和 GUI 仍然按横着的图处理，各条路径不一致。

## 影响

- 带方向标记的照片现在能正常处理，输出也是转正的。
- 不带标记的图，结果和以前逐像素相同（已验证）。所以"与原版 Clear2Fog 逐像素一致"只对不带标记的图成立。
