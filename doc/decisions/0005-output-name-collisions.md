# 0005：同名输出加 `_2`、`_3`，不覆盖

- 状态：已采纳
- 日期：2026-11-19
- 相关：`core/io.py`（`unique_stems`）、`core/pipeline.py`（`run_folder`）、`degradations/weather/fog.py`（`run_cli`）；提交 `b3f8e78`

## 背景

- 处理文件夹时，结果一律保存为 `<主名>.png`，所以同一文件夹里的 `a.jpg` 和 `a.png` 会写到同一个文件（连同 `.json`），后处理的那张悄悄覆盖前一张。
- `degfw fog` 把所有结果放进一个文件夹，所以不同输入文件夹里的同名图片也会互相覆盖，`fog_run.json` 里的记录同样被覆盖。

## 决定

`core/io.unique_stems`：按输入的排序，第一张保留原名，之后主名已被占用的（不区分大小写，和 Windows 一致）加 `_2`、`_3`……

- `run_folder`：按输出的子文件夹分别处理，保持原来的文件夹结构。
- `degfw fog`：对全部输入一起处理，改了名的会打印出来；`fog_run.json` 以输出名为键，并列出每张输入对应的输出文件。

## 考虑过的方案

- **遇到同名直接报错**：一对冲突就让整批处理停下。
- **输出名保留原扩展名**（如 `a.jpg.png`）：所有文件名都会变，按文件名配对原图和结果的代码都要改。
- **`degfw fog` 按输入文件夹分子目录输出**：改变了 `c2f.py` 的输出布局。

## 影响

- 没有冲突时文件名和以前一样。
- 有冲突时，哪一张加 `_2` 取决于排序（例如 `a.jpg` 排在 `a.png` 前面，所以是 `a.png` 那张变成 `a_2.png`）。
  原图和结果的对应关系始终可以从结果旁 `.json` 里的 `source` 查到。
