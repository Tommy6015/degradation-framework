# 0008：雾的景深：有 LiDAR 时用点云校正 Depth Pro 的尺度

- 状态：已采纳
- 日期：2026-11-24
- 相关：`core/lidar.py`、`datasets/tumtraf.py`、`degradations/weather/fog.py`（`lidar_scaled_depth`、`degfw fog --lidar`）；
  测试 `tests/test_lidar.py`、`tests/degradations/test_fog.py`

## 背景

- 雾的强度由能见度给定，Koschmieder 公式里用的是每个像素的距离。景深的尺度错了，能见度这个强度标签就不对；
  任务书要求退化的强度已知（F4）。
- Depth Pro 只看一张图来估算以米为单位的景深。在 TUMTraf A9 的路侧相机 `s110_camera_basler_south2_8mm` 上实测：
  取 5 帧，和 `s110_lidar_ouster_south` 投影到图上的点比较。
  - **Depth Pro 的景深只有 LiDAR 的 0.12–0.13 倍：** 场景景深的中位数，Depth Pro 估成 2.7 m，LiDAR 是 22 m；
    给它标定里的真实焦距，也只到 0.15 倍。高处俯拍的街景被当成了微缩模型。
  - **后果：** 标称能见度 100 m 的雾，看起来只相当于约 800 m。
  - **但这个比值很稳定：** 近处（< 30 m）和远处（≥ 60 m）几乎一样，10%–90% 分位在 0.12–0.13 之间。
    也就是说，相对结构是对的，错的主要是整体尺度。
  - **帧间跳动：** 按 LiDAR 算出的尺度，每帧在 7.7 到 8.2 之间跳动（约 7%），序列里雾的浓度会跟着跳。
- TUMTraf A9 的标注文件（OpenLABEL 格式）里有相机内参、相机相对 LiDAR 的位姿，还有每一帧点云对应的图片文件名，
  不需要另外的标定文件。

## 决定

- **用法：** `degfw fog --lidar 文件夹`。给了就用 LiDAR 校正景深的尺度，不给时行为不变。
- **每张图的处理：**
  1. 按图片文件名，在标注里找到这一帧的点云和标定（`datasets/tumtraf.py`）。同一张图有几台 LiDAR，就把几台的点都用上。
  2. 把点投影到图上（`core/lidar.py`）。景深取相机坐标系里的 z，也就是沿光轴的距离，和 Depth Pro 的景深是同一个量。
  3. 尺度 = 中位数(LiDAR 景深 ÷ Depth Pro 景深)，景深 = Depth Pro × 尺度。之后的大气光估计和加雾都不变；
     判断天空（≥ 1000 m）和计算整批的平均大气光，用的也是校正后的景深。
  4. **退回：** 图里的点少于 50 个、找不到点云文件，或者标定对应的图像尺寸和图片不同时，这张图只用 Depth Pro；
     终端会提示，`fog_run.json` 里写明原因。
- **记录：** `fog_run.json` 里每张图记下景深来源、尺度、用到的点数、校正后的残差（中位数和 90% 分位），以及用到的标注和点云文件。
- **TUMTraf 标注的坐标约定：** `pose_wrt_parent` 把父坐标系里的坐标变换到子坐标系，即 X_子 = P · X_父。
  这是把点投影到图上核对出来的：按反方向变换时，点和画面完全对不上。
- **数据集相关的部分只放在 `datasets/tumtraf.py`：** 它把每张图对应的点云和标定整理成 `LidarView`（定义在 `core/lidar.py`）。
  换一个数据集，再写一个提供 `views_for(图片文件名)` 的读取器就行，`core/lidar.py` 和雾的代码都不用改。

## 考虑过的方案

- **只用点云，不用 Depth Pro**：投影后只有 0.2% 的像素上有点，而且只在第 134 到 852 行（图像共 1200 行）；
  图像下方三分之一的近处路面和近处的车完全没有点。这些区域只能插值或外推，而近处恰恰是加雾时最要算准的地方。没选。
- **有点的像素直接用 LiDAR 的值，其余用校正后的 Depth Pro**：点是稀疏的，雾里会出现一个个点状的斑。
  校正后的误差中位数已经只有 2–3%，这样做好处不大。没选。
- **分区域的尺度（由各点插值出一张尺度图）**：比值在近处和远处几乎一样，一个全局尺度就够了。以后换到别的相机发现不够，再加。
- **整个序列共用一个尺度**：每帧单独校正后，5 帧的景深中位数都是 22.0 ± 0.1 m，Depth Pro 的帧间跳动已经消除了，不需要。
- **补偿相机和 LiDAR 之间的时间差**（30–80 ms）：运动的车会差约 1 m，但取了中位数，对尺度几乎没有影响。没做。

## 影响

- **有 LiDAR 的数据：** 雾的浓度和标称能见度一致。5 张 Demo 图上，尺度在 7.66 到 8.22 之间，
  有点的地方，校正后景深的中位相对误差为 2.1% 到 2.6%。
- **不给 `--lidar` 时：** 结果逐像素不变（回归测试 `test_fog_matches_reference`）。
- **没有 LiDAR 的数据集仍然有这个问题：** 只用 Depth Pro 时，路侧相机上的雾可能比标称能见度弱很多。
  要不要另找办法校正尺度（例如有相机标定时，用相机高度和地平面算出路面的距离），在定强度等级（F4）时一起决定。
- **只有 `degfw fog` 能用：** `degfw run fog`、`apply` 和 GUI 暂时用不上 LiDAR，因为退化接口只拿到像素，拿不到图片的来源；
  要等 M3 的接口扩展（来源信息）。
- **支持范围：** 只支持 TUMTraf 的 OpenLABEL 标注，以及 ascii 和 binary 两种 PCD；不需要新的依赖。
