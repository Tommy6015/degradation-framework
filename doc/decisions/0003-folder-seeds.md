# 0003：批量处理时，每张图的种子由（种子, 相对路径）算出

- 状态：已采纳（取代原来的"种子 + 序号"）
- 日期：2026-11-19
- 相关：`core/pipeline.py`（`image_seed`、`Pipeline.run_folder`）；提交 `21b2ef7`

## 背景

原来处理文件夹时，第 i 张图（按排序）的种子是 `配置的种子 + i`，有两个问题：

- 文件夹里多一张或少一张图，排在它后面的所有图种子都会变，结果也跟着变；
- 种子 0 和种子 1 跑出的两版数据集只是错开一位：种子 0 那一版的第 k+1 张图，和种子 1 那一版的第 k 张图用的是同一组随机数。

## 决定

`image_seed(seed, rel_path)`：把图片相对输入文件夹的路径（`/` 分隔，Unicode NFC 规范化）做 SHA-256，和配置的种子一起交给
`numpy.random.SeedSequence`，得到一个 63 位的种子。和原来一样，实际用的种子记在每张图的 `.json` 里，
可以用 `run_file(..., seed=那个值)` 单独重做这张图。

## 考虑过的方案

- **按文件名而不是相对路径**：不同子文件夹里的同名图片会得到同一个种子。
- **按图像内容的哈希**：改一个像素种子就变；而且要先读图才知道种子。
- **保持种子 + 序号**：就是上面的两个问题。

## 影响

- 每张图的结果只取决于它自己的路径和配置的种子。
- 用同一个配置重新处理文件夹，结果和 2026-11-19 之前不同；以前生成的图仍可按各自 `.json` 里的种子复现。
- 改名或移动图片后，它的种子会变。
