# 0010：退化能拿到像素以外的来源信息；雾只有一份处理代码

- 状态：已采纳
- 日期：2026-11-25
- 相关：`degradation_fw/core/context.py`（`Context`）、`core/base.py`、`core/pipeline.py`、`core/params.py`（`Folder`）、
  `degradations/weather/fog.py`（`FogRun`）；测试 `tests/test_core.py`、`tests/degradations/test_fog.py`；
  [决策 0008](0008-fog-lidar-depth-scale.md)；roadmap"要决定的事"第 2、3 条

## 背景

- **统一接口只交出像素：** 框架的退化接口是 `apply(图像, 随机数, 参数)`。注册的退化（`degfw run`、`degfw apply`、配置文件、界面都走这条路）
  只知道这一张图的像素。
- **雾需要像素以外的东西：**
  - **图片文件：** EXIF 里的焦距（Depth Pro 用），以及文件名（找这张图对应的 LiDAR 点云，[决策 0008](0008-fog-lidar-depth-scale.md)）；
  - **同一次运行的其他图：** 没有天空的图用整批的平均大气光；
  - **LiDAR 文件夹。**
- **所以雾有了两份代码：** M1 时为了和原版 `c2f.py` 一致，另做了雾自己的命令 `degfw fog`，它自己读文件、整批处理；
  之后 LiDAR 校正也只加在了这里。注册的雾那一份落后了：没有天空时一律用 0.8，不用 EXIF 焦距，也用不了 LiDAR。
  同样的图，两条路得到的结果不同。
- **注册的这条路不能去掉：** 配置文件（F10）、多种退化按顺序组合（F5）、新增退化只加一个适配器（N1）都靠它。

## 决定

- **来源信息 `Context`：** Pipeline 处理每张图的每个步骤时，除了像素，再交给退化一个 `Context`：
  - `source`：这张图的文件；内存里的图（如界面的预览）为 `None`；
  - `batch`：这次运行的全部输入文件；
  - `shared`：整次运行共用的字典，每个步骤一个。只需要算一次的东西放在这里，下一次运行重新开始；
  - `info`：退化为这张图写下的记录，写进 `.json` 里这个步骤下的 `info`。
- **接口改为 `apply(image, rng, context, **params)`。** 参数不能叫 `image`、`rng`、`context`，注册时检查。
  不需要来源信息的退化忽略 `context`。
- **雾只有一份代码 `FogRun`：** 一次运行一个；读 EXIF 焦距、Depth Pro、LiDAR 校正、大气光（从天空估，或者整批平均，第一次需要时才算）、
  加雾，都只在这里。`degfw fog` 和注册的雾都调用它；注册的雾把它放在 `context.shared` 里，整次运行共用。
- **注册的雾加参数 `lidar`：** 新的参数类型 `Folder`，值是文件夹路径，空表示不用。给了但文件夹不存在时，开始处理前就报错。
- **`degfw fog` 不变：** 用法、输出文件和 `fog_run.json` 都和以前一样。
- **不跨运行沿用平均大气光：** Depth Pro 引擎在进程里只加载一次，被各次运行共用。`FogRun` 每次加雾前，把引擎里的平均大气光设成本次运行的值，
  所以在同一个进程里先后运行（比如界面里）时，不会用到上一次运行留下的值。
- **切换精度时释放旧模型的显存：** 引擎换成另一种精度（fp16 ↔ float32）前，先删掉旧模型并清空 PyTorch 的显存缓存。
  否则旧模型的显存留在缓存里，下一个 float32 模型（约 8 GB）只能更多地借用内存：完整测试因此从不到 4 分钟变成 10 分钟以上。
  以后在界面里切换 fp16 开关也会遇到。
- **顺带的清理：** 删掉示例退化 `gaussian_noise`（连同删掉后变空的 `sensor/` 文件夹）和空的占位文件 `lens/lens_dirt.py`。
  框架自己的测试改用 `tests/conftest.py` 里的两个测试用退化（`test_noise`、`test_context`），它们只在测试里注册。

## 考虑过的方案

- **删掉注册的雾，只留 `degfw fog`**：最简单，但雾就没法写进配置文件，也没法和其他退化组合（F5、F10、N1）。没选。
- **界面直接调用 `degfw fog` 的代码**：界面里要为雾单独写一条路，输出格式和别的退化不同，也没法用 `degfw apply` 复现；
  以后再有退化需要来源信息，又要再写一条。没选。
- **把 LiDAR 文件夹放进来源信息，而不是作为雾的参数**：以后数据集适配器（M6）读入数据集时，点云是数据集的一部分，放在来源信息里更合理。
  但现在只有雾用它；作为参数，可以直接写进配置文件和 `-p`，也自动记进元数据。暂时作为参数，M6 时再看。
- **在雾的模块里用全局变量缓存整批的结果**：不同运行之间会互相影响，比如上一次运行的平均大气光留到下一次。没选，改用每次运行一份的 `shared`。
- **一个步骤开始前先对整批调用一次"准备"方法**：要给基类再加一个方法；而雾的平均大气光只在遇到没有天空的图时才需要算，
  放在第一次用到时算更省时间。没选。

## 影响

- **注册的雾和 `degfw fog` 结果相同：** 用两组 Demo 数据逐像素比较：`Phase 2\Input\Demo`（4 张，其中 1 张没有天空）和
  `Phase 2\Input\a9_dataset_r02_s03_Demo`（5 张，带 LiDAR）。覆盖 fp16 能见度 50 和 100、float32 能见度 100、有 LiDAR 和没有 LiDAR，
  走 `degfw run fog` 和 `degfw apply` 两种方式，共 32 张图，全部和 `degfw fog` 逐像素相同，每张图记录的景深来源和大气光来源也相同。
  自动测试：`test_fog_degradation_same_as_fog_command`（有 / 没有 LiDAR 各一次）。
- **`degfw fog` 前后不变：** 改动前先跑了 4 次作基准（27 张图，包括没有天空、有 LiDAR、float32 的情况），改动后再跑：
  输出图全部逐像素相同，`fog_run.json` 完全相同。回归测试 `test_fog_matches_reference` 也通过。
- **注册的雾的结果变了**（以前用 `degfw run fog` 或配置文件生成的雾图）：
  - 没有天空的图：以前固定用 0.8，现在用整批的平均值，例如 Demo 里那张没有天空的图，平均值是 [0.718, 0.746, 0.807]；
  - 带 EXIF 焦距的照片：现在用 EXIF 焦距，和 `degfw fog` 一样。TUMTraf 的图没有 EXIF 焦距，不受影响；
  - 有天空、没有 EXIF 焦距的图，以及内存里的单张图（`get("fog")(图像)`、界面的预览）：不变。回归测试的参考图就是这样生成的。
- **`.json` 多了 `info`：** 雾记下大气光来源、景深的最小值和中位数、景深来源（用了 LiDAR 时有尺度、点数、误差），
  用了整批平均时还有平均值。字段和 `fog_run.json` 里每张图的一样。
- **接口变了：** 新写的退化，`apply` 要多接一个 `context` 参数（`_template.py` 已更新）。配置文件里用了 `gaussian_noise` 的要换掉，
  `configs/example.yaml` 已经改成雾。
- **仍然存在的问题：**
  - 没有天空的图，结果取决于同一批里有哪些图（roadmap"要决定的事"第 3 条）。现在两条路径只是以同样的方式依赖批次。
  - 单独重做一张这样的图（`run_file`）时，要传入同一批图 `batch=` 才能得到同样的结果。`info` 里记着用过的平均值，以后可以考虑直接按记录重做。
  - 两个命令读到的图可能不同：`degfw fog` 只读文件夹本层的 .png .jpg .jpeg，`degfw run` / `apply` 也读子文件夹和更多格式。整批平均按各自读到的图算。
- **顺带看到的一点：** a9 Demo 里有一张图，只用 Depth Pro 时没有天空；用 LiDAR 校正尺度（约 × 8）后，远处的像素超过了 1000 m，就用上了它自己的天空。
  景深尺度不对，也会让"有没有天空"的判断出错。这一点在定第 3 条时要考虑。
